# FreeRTOS 任务切换

`RTOS`的核心是任务管理，而任务管理的重中之重是任务切换，系统中的任务切换的过程决定了操作系统的运行效率和稳定性，尤其对于实时操作系统。
**任务切换的核心**
- 触发 `PendSV` 异常
- 保存当前任务的上下文
- 恢复最高优先级就绪任务的上下文

## 1. 关键 PendSV 异常

1. `PendSV`（Pended Service Call，可挂起服务调用），是一个对`RTOS`非常重要的异常，对任务切换起到了至关重要的作用，是任务切换的执行者
2. PendSV的中断优先级是可以编程的，用户可以根据实际的需求，对其进行配置，关键特性，将其中断优先级设置为最低，在所有中断都完成后，才执行`PendSV`的中断，进行任务切换
3. PendSV的中断由将中断控制状态寄存器（ICSR）中`PENDSVSET`为置`1`触发
```c
    /* 触发PendSV异常中断 */
    ICSR->PENDSVSET = 1 
```
## 2. 触发任务切换的两种方式

### 2.1 手动切换任务

手动执行`taskYIELD()`,调用该API，将强制触发任务切换，这里实际也是触发`PendSV`异常
```c
    #define taskYIELD()                        portYIELD()

    #define portYIELD()                                
    {                                                  
        portNVIC_INT_CTRL_REG = portNVIC_PENDSVSET_BIT; 
        __dsb( portSY_FULL_READ_WRITE );                          
        __isb( portSY_FULL_READ_WRITE );                           
    }
```
> 例如在中断服务函数，进行完对于的操作后，需要手动执行`portYIELD_FROM_ISR()`函数进行任务切换

### 2.2 SysTick周期性中断

在启动任务调度后，会开始滴答定时器的中断，在其中断服务函数中，主要进行的就是触发`PendSV`异常，进行任务切换
```c
void xPortSysTickHandler( void )
{
    vPortRaiseBASEPRI();
    {
        /* Increment the RTOS tick. */
        if( xTaskIncrementTick() != pdFALSE )
        {
           /* 触发PendSV异常中断 */
            portNVIC_INT_CTRL_REG = portNVIC_PENDSVSET_BIT;
        }
    }

    vPortClearBASEPRIFromISR();
}
```
## 3. PendSV 异常中断服务函数

在前面触发了`PendSV`异常后，会跳转至`PendSV`异常的中断服务函数，进行任务切换：
```c
__asm void xPortPendSVHandler(void)
{
    extern uxCriticalNesting;
    extern pxCurrentTCB; /* 指向当前激活的任务 */
    extern vTaskSwitchContext;

    PRESERVE8

    mrs r0, psp     /* PSP内容存入R0 */
    isb /* 指令同步隔离,清流水线 */

    ldr r3, = pxCurrentTCB /* 当前激活的任务TCB指针存入R2 */
    ldr r2,[r3]

    stmdb r0 !,{r4 - r11} /* 保存剩余的寄存器,异常处理程序执行前,硬件自动将xPSR、PC、LR、R12、R0-R3入栈 */
    str r0,[r2] /* 将新的栈顶保存到任务TCB的第一个成员中 */

    stmdb sp !,{r3, r14} /* 将R3和R14临时压入堆栈，因为即将调用函数vTaskSwitchContext,调用函数时,返回地址自动保存到R14中,所以一旦调用发生,R14的值会被覆盖,因此需要入栈保护; R3保存的当前激活的任务TCB指针(pxCurrentTCB)地址,函数调用后会用到,因此也要入栈保护*/
    mov r0,#configMAX_SYSCALL_INTERRUPT_PRIORITY /* 进入临界区 */
    msr basepri,r0
    dsb /* 数据和指令同步隔离 */
    isb
    bl vTaskSwitchContext /* 调用函数,寻找新的任务运行,通过使变量pxCurrentTCB指向新的任务来实现任务切换 */
    mov r0,#0 /* 退出临界区*/
    msr basepri,r0
    ldmia sp !,
    {r3, r14} /* 恢复R3和R14*/

    ldr r1,[r3] 
    ldr r0, [r1] /* 当前激活的任务TCB第一项保存了任务堆栈的栈顶,现在栈顶值存入R0*/
    ldmia r0 !,{r4 - r11} /* 出栈*/
    msr psp,r0
    isb
    bx r14 /* 异常发生时,R14中保存异常返回标志,包括返回后进入线程模式还是处理器模式、使用PSP堆栈指针还是MSP堆栈指针，当调用 bx r14指令后，硬件会知道要从异常返回，然后出栈，这个时候堆栈指针PSP已经指向了新任务堆栈的正确位置，当新任务的运行地址被出栈到PC寄存器后，新的任务也会被执行。*/
    nop
}
```
>FreeRTOS 的任务上下文切换主要发生在 PendSV_Handler 中。进入 PendSV 异常时，Cortex-M 硬件会自动把当前任务的一部分寄存器压入任务栈，比如 r0-r3、r12、lr、pc、xPSR。软件再手动保存剩下的 r4-r11，以及必要时保存 FPU 寄存器。然后把当前 PSP 保存到当前任务的 TCB 中，调用 vTaskSwitchContext() 选择下一个任务，再从新的 TCB 中取出栈顶指针，恢复新任务的寄存器，最后通过异常返回恢复新任务执行。

## 4. FreeRTOS确定下一个要执行的任务

在前面的`PendSV`异常中使用了API函数`vTaskSwitchContext`更新了下一个要执行的任务，而这个API函数本质又是执行了宏`taskSELECT_HIGHEST_PRIORITY_TASK()`，来找到下一个执行的任务

FreeRTOS提供了两种从任务优先级记录中查找优先级最高任务优先等级的方式，一种是由纯C代码实现的，这种方式适用于所有运行FreeRTOS的MCU；另外一种方式则是使用了硬件计算**前导零**的指令，因此这种方式并不适用于所有运行FreeRTOS的MCU，而仅适用于具有有相应硬件指令的MCU。

软件实现：
```c
#define taskSELECT_HIGHEST_PRIORITY_TASK()                                
    {                                                                         
        UBaseType_t uxTopPriority = uxTopReadyPriority;                       
                                                                            
        /* Find the highest priority queue that contains ready tasks. */      
        while( listLIST_IS_EMPTY( &( pxReadyTasksLists[ uxTopPriority ] ) ) ) 
        {                                                                     
            configASSERT( uxTopPriority );                                    
            --uxTopPriority;                                                  
        }                                                                    
                                                                         
        listGET_OWNER_OF_NEXT_ENTRY( pxCurrentTCB, &( pxReadyTasksLists[ uxTopPriority ] ) ); 
        uxTopReadyPriority = uxTopPriority;                                      
    } 
```
> 从高到低，通过一个循环从就绪任务列表中找到是否有对应优先级的任务就绪

硬件实现：
```c
#define taskSELECT_HIGHEST_PRIORITY_TASK()                                                  
    {                                                                                           
        UBaseType_t uxTopPriority;                                                              
                                                                                                      
        portGET_HIGHEST_PRIORITY( uxTopPriority, uxTopReadyPriority );                          
        configASSERT( listCURRENT_LIST_LENGTH( &( pxReadyTasksLists[ uxTopPriority ] ) ) > 0 ); 
        listGET_OWNER_OF_NEXT_ENTRY( pxCurrentTCB, &( pxReadyTasksLists[ uxTopPriority ] ) );   
    } 

    #define portGET_HIGHEST_PRIORITY( uxTopPriority, uxReadyPriorities )    uxTopPriority = ( 31UL - ( uint32_t ) __clz( ( uxReadyPriorities ) ) )
```
> 通过`__clz`这个硬件指令快速找到一个32位变量中，从高往低数的前置0的个数，从而确定就绪的最高优先级
