# FreeRTOS任务延时函数

`FreeRTOS`为用户提供了任务延时的API函数，调用这些函数，可以实现对当前任务的延时阻塞，切换至其他任务执行，到达延时时间后，切换回当前任务执行。三个主要的任务延时函数如下：
- `vTaskDelay()`: 任务延时函数，延时单位：系统时钟节拍
- `vTaskDelayUntil()`: 任务绝对延时函数，延时单位：系统时钟节拍
- `xTaskAbortDelay()`: 终止任务延时函数

## 函数`vTaskDelay()`

`vTaskDelay()`程序源码如下：
```c
#if ( INCLUDE_vTaskDelay == 1 )

    void vTaskDelay( const TickType_t xTicksToDelay )
    {
        BaseType_t xAlreadyYielded = pdFALSE;

        /* 只有在延时时间大于0的时候， 
         * 才需要进行任务阻塞， 
         * 否则相当于强制进行任务切换，而不阻塞任务 
         */ 
        if( xTicksToDelay > ( TickType_t ) 0U )
        {
            configASSERT( uxSchedulerSuspended == 0 );
            vTaskSuspendAll();
            {
                traceTASK_DELAY();

                /* 将任务添加到阻塞态任务列表中 */
                prvAddCurrentTaskToDelayedList( xTicksToDelay, pdFALSE );
            }
            /* 恢复任务调度器运行， 
             * 调用此函数会返回是否需要进行任务切换 
             */
            xAlreadyYielded = xTaskResumeAll();
        }
        else
        {
            mtCOVERAGE_TEST_MARKER();
        }

        /* 根据标志进行任务切换 */
        if( xAlreadyYielded == pdFALSE )
        {
            portYIELD_WITHIN_API();
        }
        else
        {
            mtCOVERAGE_TEST_MARKER();
        }
    }

#endif /* INCLUDE_vTaskDelay */
```
由上述源码可知：
1. 要使用`vTaskDelay()`，必须开启宏`INCLUDE_vTaskDelay`
2. 该函数只针对当前任务，不能在其他任务中去使用
3. 函数`vTaskDelay()`传入的参数`xTicksToDelay`是任务被延时的具体延时时间，时间的单位为系统时钟节拍，由`FreeRTOSconfig.h`中的宏`configTICK_RATE_HZ`决定
4. 如果传入的参数为`0`，则强行进行一次任务切换
5. 函数中实际的工作函数为：`prvAddCurrentTaskToDelayedList`，这个函数主要做了下面两个内容的工作：
- 将当前任务从`就绪列表`移动至`阻塞列表`
- 更新全局变量`xNextTaskUnblockTime`，这个记录了下一个最新苏醒的任务，在滴答定时器的中断服务函数中唤醒
  
## 函数`vTaskDelayUntil()`

函数`vTaskDelayUntil()`用于以一个绝对的时间阻塞任务，适用于需要按照一定频率运行的任务

使用案例：
```c
void PeriodcTask(void *pvParameters)
{
    static TickType_t lastWakeTime;
    const TickType_t cycleTicks = pdMs_TO_TICKD(100);

    // 初始化：获取任务第一次启动时的系统节拍
    lastWakeTime = xTaskGetTickCount();

    for(;;)
    {
        /*************************
         * 业务逻辑（执行耗时不定）
         *************************/
        printf("周期任务执行\r\n");

        // 阻塞延时，保证严格100ms周期
        vTaskDelayUntil(&lastWakeTime, cycleTicks);
    }
}
```

> 为什么`vTaskDelayUntil()`更适合按照一定频率运行的任务？
答：因为函数`vTaskDelayUntil()`是按照绝对时间来进行任务阻塞的，而函数`vTaskDelay()`是按照相等时间来进行任务阻塞的。举一个简单的例子，传感器数据上报任务，每隔100ms进行上报。如果是相对时间阻塞，那当上报时间为2ms,再阻塞100ms时，周期为102ms。但是有时候，传感器上报时间可能不为固定的2ms，这时周期就会存在一定的误差。但是当使用绝对时间进行阻塞时，即使传感器的上报时间不确定，系统也会更具上次阻塞结束时间，来固定周期上报。比如设置周期为100ms，那当上报时间为2ms时，阻塞时间就为98ms；当上报时间为4ms时，阻塞时间就为96ms

## 函数`xTaskAbortDelay()`

函数原型如下：
`BaseType_t xTaskAbortDelay(TaskHandle_t xTask)`

函数`xTaskAbortDelay()`用于终止处于阻塞态的任务的阻塞，它主要做了以下工作：
1. 将指定任务从阻塞列表转移至就绪列表
2. `抢占式任务调度`: 必须进行任务切换，因为转移的阻塞任务优先级可能更高
3. 如果任务是因为事件而导致阻塞的，还需要将该任务从当前事件列表中移除
