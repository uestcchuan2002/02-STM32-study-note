# `FreeRTOS`的系统时钟节拍

每个操作系统都需要系统时间节拍。系统时钟节拍是进行多线程任务切换的关键，在`FreeRTOS`中，系统时钟节拍决定了时间片轮转的任务调取。

在`FreeRTOS`中，使用了一个专门的全局变量`xTickCount`来记录系统的时钟节拍数，它在`task.c`文件中有如下定义：
```c
PRIVILEGED_DATA static volatile TickType_t xTickCount = ( TickType_t ) configINITIAL_TICK_COUNT;

#ifndef configINITIAL_TICK_COUNT
    #define configINITIAL_TICK_COUNT    0
#endif
```
这就意味在没有用户定义的情况下，`xTickCount`的初始化都是`0`;

## 1. 系统时钟节拍源

既然`FreeRTOS`的系统时钟计数是一个全局变量，那肯定存在一个**系统时钟源**时这个变量发生规律变化，那这个系统时钟源是什么呢？

在大多数情况下`FreeRTOS`的系统时钟源为`CPU`的`SYSTICK`定时器，但是也可由用户在移植过程中指定为其他定时器。

在系统的任务调度器启动过程中，会实现对于`SYSTICK`定时器的配置与开启，具体的实现路径与操作如下：
- `vTaskStartScheduler()`启动任务调度器
- 函数内容调用`xPortStartSheduler()`实现真正的任务调度操作
- 在`xPortStartSheduler()`中会执行下面操作：
    - `portNVIC_SHPR3_REG |= portNVIC_SYSTICK_PRI`:设置`SYSTICK`定时器的优先级为最低优先级
    - 调用`vPortSetupInterrupt()`函数对`SYSTICK`定时器进行配置

`vPortSetupInterrupt()`函数主要内容：
```c
    __weak void vPortSetupTimerInterrupt( void )
    {
        // 清空 SYSTICK 定时器的控制状态寄存器
        portNVIC_SYSTICK_CTRL_REG = 0UL;
        // 清空 SYSTICK 定时器当前的计数值
        portNVIC_SYSTICK_CURRENT_VALUE_REG = 0UL;
        // 设置自动重装置，实现系统时钟节拍为：configTICK_RATE_HZ
        portNVIC_SYSTICK_LOAD_REG = ( configSYSTICK_CLOCK_HZ / configTICK_RATE_HZ ) - 1UL;
        
        /*
            portNVIC_SYSTICK_CLK_BIT: 设置 SYSTICK 定时器时钟频率与cpu频率相同
            portNVIC_SYSTICK_INT_BIT： 开启 SYSTICK 定时器计数清零中断，定时器为向下计数
            portNVIC_SYSTICK_ENABLE_BIT： 开启 SYSTICK 定时器计数
        */

        portNVIC_SYSTICK_CTRL_REG = ( portNVIC_SYSTICK_CLK_BIT | portNVIC_SYSTICK_INT_BIT | portNVIC_SYSTICK_ENABLE_BIT );
    }
```

## 2. 系统时钟节拍处理

既然在启动任务调度的函数中，开启了`SYSTICK`定时器，那系统时钟节拍的处理自然是在`SYSTICK`定时器的中断服务函数中进行。其中断服务函数如下所示：
```c
void SysTick_Handler(void)
{
    // HAL库的时基增加，与FreeRTOS无关
    HAL_IncTick();
    // 确定任务调度器是否开启，只有开启后才能进行任务调度操作
    if (xTaskGetSchedulerState() != taskSCHEDULER_NOT_STARTED) 
    {
        // 进行`SYSTICK`定时器的底层中断服务
        xPortSysTickHandler();
    }
}
```
开启任务调度后，会调用函数`xPortSysTickHandler()`执行系统时钟节拍处理，其函数原型如下：
```c
void xPortSysTickHandler( void )
{
   /*
        屏蔽所有受FreeRTOS管理的中断
        因为SYSTICK`定时器的中断优先级设置为最低，防止其他中断干扰
   */
    vPortRaiseBASEPRI();
    {
        /* 时钟节拍数加1，并且通过返回值判断是否需要进行任务切换 */
        if( xTaskIncrementTick() != pdFALSE )
        {
            // 触发PendSV进行任务切换
            portNVIC_INT_CTRL_REG = portNVIC_PENDSVSET_BIT;
        }
    }
    /* 退出中断屏蔽，恢复正常 */
    vPortClearBASEPRIFromISR();
}
```
在上述底层中断服务函数中，会执行`xTaskIncrementTick()`函数，来实现系统时钟节拍的自加，并通过内部判断返回来实现任务的切换，那其内部是否如何去判断一个系统时钟中断后，是否需要进行任务切换的呢？因此对其源码的阅读就显得是否的有必要！`xTaskIncrementTick()`的主要实现过程如下：
```c
 BaseType_t xTaskIncrementTick( void )
{
    TCB_t * pxTCB;
    TickType_t xItemValue;
    BaseType_t xSwitchRequired = pdFALSE;

    /*
        判读任务调度器是否运行
        只有任务调度器正在运行的情况下，才作相应处理
    */
    if( uxSchedulerSuspended == ( UBaseType_t ) pdFALSE )
    {
        
        const TickType_t xConstTickCount = xTickCount + ( TickType_t ) 1;

        /* 此全局变量为系统使用节拍计数器，实现其加1 */
        xTickCount = xConstTickCount;

        /*
            如果系统时钟节拍计数器的值为0， 
            说明系统时钟节拍计数器已经溢出了 
            因此需要作相应的处理
        */
        if( xConstTickCount == ( TickType_t ) 0U ) 
        {
            /*  切换阻塞态任务列表 
                FreeRTOS定义了两个阻塞态任务列表 
                就是为了解决系统节拍计数器溢出的问题 
            */
            taskSWITCH_DELAYED_LISTS();
        }
        else
        {
            mtCOVERAGE_TEST_MARKER();
        }

        /* 检查是否有阻塞任务阻塞超时， 
         * 阻塞态任务列表中的阻塞任务时按照阻塞超时时间排序的， 
         * 因此，只要按顺序检查出一个未超时的阻塞任务， 
         * 就没有必要检查下去了 
         */
        if( xConstTickCount >= xNextTaskUnblockTime )
        {
            for( ; ; )
            {
                /* 判断阻塞态任务列表中是否有阻塞任务 */
                if( listLIST_IS_EMPTY( pxDelayedTaskList ) != pdFALSE )
                {
                    /* 此全局变量用于记录下一个阻塞任务的阻塞超时系统节拍， 
                     * 因此阻塞态任务列表中没有阻塞任务， 
                     * 因此将此全局变量设置为最大值 
                     */ 
                    xNextTaskUnblockTime = portMAX_DELAY; 
                    break;
                }
                else
                {
                    /* 获取阻塞态任务列表中第一个阻塞任务的任务状态列表项值 
                     * 这个值记录了，该阻塞任务的阻塞超时系统时钟节拍 
                     */ 
                    pxTCB = listGET_OWNER_OF_HEAD_ENTRY( pxDelayedTaskList ); 
                    xItemValue = listGET_LIST_ITEM_VALUE( &( pxTCB->xStateListItem ) );

                    /* 判断阻塞任务的阻塞时间是否还未超时 */ 
                    if( xConstTickCount < xItemValue )
                    {
                        /* 如果阻塞任务的阻塞时间还未超时， 
                         * 将记录下一个阻塞任务阻塞超时时间的全局变量设置为最大值， 
                         * 并退出循环，因为阻塞态任务列表中没有超时的阻塞任务 
                         */ 
                        xNextTaskUnblockTime = xItemValue;
                        break; 
                    }
                    else
                    {   
                        /* 已经超时了，需要将阻塞任务移动就绪列表 */
                        mtCOVERAGE_TEST_MARKER();
                    }

                    /* 将阻塞时间超时的阻塞任务， 
                     * 从阻塞态任务列表中移除 
                     */
                    listREMOVE_ITEM( &( pxTCB->xStateListItem ) );

                    /* 判断阻塞任务是否正在等待事件发生， 
                     * 如果是，那么设置的等待时间（阻塞时间）已经超时， 
                     * 任务阻塞可能是等待事件引起的， 
                     * 也可能是调用FreeRTOS的延时函数引起的 
                     */ 
                    if( listLIST_ITEM_CONTAINER( &( pxTCB->xEventListItem ) ) != NULL )
                    {
                        /* 等待事件的时间已经超时， 
                         * 将任务的事件列表项，从等待的事件列表中移除 
                         */ 
                        listREMOVE_ITEM( &( pxTCB->xEventListItem ) );
                    }
                    else
                    {
                        mtCOVERAGE_TEST_MARKER();
                    }

                    /* 将阻塞超时的任务添加到就绪态任务列表中 */
                    prvAddTaskToReadyList( pxTCB );

                    /* 此宏用于启用抢占式调度 */ 
                    #if ( configUSE_PREEMPTION == 1 )
                        {
                            /* 在抢占式调度中 
                             * 如果阻塞超时的任务优先级高于当前系统正在运行的任务， 
                             * 那么阻塞超时的任务将抢占CPU的使用权， 
                             * 因此需要进行任务切换 
                             */
                            if( pxTCB->uxPriority >= pxCurrentTCB->uxPriority )
                            {
                                /* 标记需要进行任务切换 */ 
                                xSwitchRequired = pdTRUE;
                            }
                            else
                            {
                                mtCOVERAGE_TEST_MARKER();
                            }
                        }
                    #endif 
                }
            }
        }

        /* 宏configUSE_TIME_SLICING用于启用时间片调度 */ 
        #if ( ( configUSE_PREEMPTION == 1 ) && ( configUSE_TIME_SLICING == 1 ) )
            {
                /* 判断当前系统正在运行的任务所在优先级就绪态任务列表中， 
                 * 是否还有其他优先级相同的任务， 
                 * 如果有，由于使能了时间片调度， 
                 * 因此需要进行任务切换， 
                 * 切换到下一个相同优先级的任务 
                 */
                if( listCURRENT_LIST_LENGTH( &( pxReadyTasksLists[ pxCurrentTCB->uxPriority ] ) ) > ( UBaseType_t ) 1 )
                {
                    /* 标记需要进行任务切换 */ 
                    xSwitchRequired = pdTRUE;
                }
                else
                {
                    mtCOVERAGE_TEST_MARKER();
                }
            }
        #endif 

       

        #if ( configUSE_PREEMPTION == 1 )
            {
                /* 此全局变量用于在系统运行的任意时刻标记需要进行任务切换 
                 * 此全局变量在此时统一处理 
                 */
                if( xYieldPending != pdFALSE )
                {
                    xSwitchRequired = pdTRUE;
                }
                else
                {
                    mtCOVERAGE_TEST_MARKER();
                }
            }
        #endif 
    }
    else
    {
        /* 此全局变量用于记录在任务调度器挂起的情况下， 
         * SysTick中断了多少次， 
         * 以在任务调度器恢复后，作相应的补偿处理 
         */ 

        ++xPendedTicks;
    }

    /* 返回是否需要进行任务切换标志 */
    return xSwitchRequired;
}
```
从上面代码可知，函数`xTaskIncrementTick()`主要进行了**系统时钟节拍处理**、**阻塞任务列表**和**时间片调度**三个方面：
- 系统时钟节拍处理:主要是对系统时钟节拍数进行了加1
- 阻塞任务列表：主要处理了是否有阻塞任务到时间了，需要将其从阻塞列表移到就绪列表
- 时间片调度:在开始了抢占式任务调度和时间片任务调度后，查看就绪列表中是否具有同优先级的任务，进行时间片的调度

## 3. 总结

综上所述，`SYSTICK`定时器产生的系统节拍是操作系统的**心跳**，只有开启了这个定时器，产生节拍，系统才能进行正在的任务切换，实现完整的功能。
