# FreeRTOS信号量

`FreeRTOS`的信号量是实现任务与任务之间、任务与中断之间的一种通信同步机制，根据不同使用场景分为下面四种：

- 二值信号量
- 计数型信号量
- 互斥信号量
- 递归型互斥信号量
  
## `FreeRTOS`二值信号量

二值信号量本质是一个长度为`1`，类型大小为`0`的，队列。它主要用于实现任务与任务之间的同步，比如说两个任务之间有明确的先后执行任务的要求，那么可以让先执行的任务在执行完后释放信号量，后执行的任务在接收信号量后才执行。

常见的二值信号量相关的API函数：
- `xSemaphoreCreateBinary()`:   使用动态的方式创建二值信号量
- `xSemaphoreCreateBinaryStatic()`: 使用静态的方式创建二值信号量
- `xSemaphoreTake()`:   获取信号量
- `xSemaphoreTakeFromISR()`:    从中断获取信号量
- `xSemaphoreGive()`:   释放信号量
- `xSemaphoreGiveFromISR()`:    从中断中释放信号量
- `xSemaphoreDelete()`: 删除信号量

*使用案例*
```c
SemaphoreHandle_t xSemaphore = NULL;

void vATask( void * pvParameters ) {
    xSemaphore = xSemaphoreCreateBinary();
    if( xSemaphore != NULL )
    {
        // The semaphore was created successfully.
    }
}

void vTask1( void * pvParameters ) {
    
    while (1) {
        xSemaphoreTake(xSemaphore, portMax_DELAY);
    }
}

void vTask2( void * pvParameters ) {
    
    while (1) {
        xSemaphoreGive(xSemaphore);
    }
}
```

## `FreeRTOS`计数信号量

计数型信号量与二值信号量在本质上的区别就是一个是容量大于1以上的队列，一个是容量仅为1的队列。这就意味着计数型信号量可以实现信号的累积，可以在最大的容积的内连续释放。只要信号量的资源不为`0`，自然也可以连续获取。

常见的计数信号量相关的API函数：
`xSemaphoreCreateCounting()`:  使用动态方式创建计数型信号量 
`xSemaphoreCreateCountingStatic()`: 使用静态方式创建计数型信号量 
`xSemaphoreTake()`: 获取信号量 
`xSemaphoreTakeFromISR()`: 在中断中获取信号量 
`xSemaphoreGive()`: 释放信号量 
`xSemaphoreGiveFromISR()`: 在中断中释放信号量 
`vSemaphoreDelete()`: 删除信号量 

*使用案例*
```c
SemaphoreHandle_t xSemaphore = NULL;

void vATask( void * pvParameters ) {
    xSemaphore = xSemaphoreCreateCounting();
    if( xSemaphore != NULL )
    {
        // The semaphore was created successfully.
    }
}

void vTask1( void * pvParameters ) {
    
    while (1) {
        xSemaphoreTake(xSemaphore, portMax_DELAY);
    }
}

void vTask2( void * pvParameters ) {
    
    while (1) {
        xSemaphoreGive(xSemaphore);
    }
}
```

## 优先级翻转

优先级翻转：高优先级的任务反而慢执行，低优先级的任务反而优先执行。
优先级翻转在抢占式内核中是非常常见的，但是在实时操作系统中是不允许出现优先级翻转的，因为优先级翻转会破坏任务的预期顺序，可能会导致未知的严重后果。
在使用二值信号量的时候，经常会遇到优先级翻转的问题。

## `FreeRTOS`互斥信号量

### 1.介绍

互斥信号量其实就是一个 拥有优先级翻转的二值信号量
- 二值信号量更适用于同步的应用
- 互斥信号量更适合那些需要互斥访问的应用(资源紧缺，需要资源保护)

### 2.优先级继承

当一个互斥信号量正在被一个低优先级的任务持有时，如果此时有一个高优先级的任务也尝试获取这个互斥信号量，那么这个高优先级的任务就会被阻塞。不过这个高优先级的任务会将低优先级任务的优先级提升到与自己相同的优先级。

### 3.互斥信号量的注意事项

优先级继承并不能完全的消除优先级翻转的问题，它只是尽可能的降低优先级翻转带来的影响。

注意：互斥信号量不能用于中断服务函数中，原因如下：
1. 互斥信号量有优先级继承的机制，但是中断不是任务，没有任务优先级，所以互斥信号量只能用于任务中，不能用于中断服务函数中。
2. 中断服务函数中不能因为要等待互斥信号量而设置阻塞时间进入阻塞态。

### 4.互斥信号量的API函数

`xSemaphoreCreateMutex()`:  使用动态方式创建互斥信号量 
`xSemaphoreCreateMutexStatic()`: 使用静态方式创建互斥信号量 
`xSemaphoreTake()`: 删除信号量 
`xSemaphoreGive()`: 获取信号量 
`vSemaphoreDelete()`: 释放信号量 

*使用案例*
```c
SemaphoreHandle_t xSemaphore = NULL;

void vATask( void * pvParameters ) {
    xSemaphore = xSemaphoreCreateMutex();
    if( xSemaphore != NULL )
    {
        // The semaphore was created successfully.
    }
}

void vTask1( void * pvParameters ) {
    
    while (1) {
        xSemaphoreTake(xSemaphore, portMax_DELAY);
        // 执行内容，后释放
        .... 

        xSemaphoreGive(xSemaphore);
    }
}

void vTask2( void * pvParameters ) {
    
    while (1) {
        xSemaphoreTake(xSemaphore, portMax_DELAY);
        // 执行内容，后释放
        .... 

        xSemaphoreGive(xSemaphore);
    }
}
```

## `FreeRTOS`递归型互斥信号量

递归型互斥信号量是一种特殊的互斥信号量，其在被获取后，可以被持有者重复获取，当然递归互斥信号量的持有者需要释放递归互斥信号
量与之获取递归互斥信号量相同的次数，递归互斥信号量才算被释放。

`xSemaphoreCreateRecursiveMutex()`: 使用动态方式创建递归互斥信号量 
`xSemaphoreCreateRecursiveMutexStatic()`: 使用静态方式创建递归互斥信号量 
`xSemaphoreTakeRecursive()`: 删除信号量 
`xSemaphoreGiveRecursive()`: 获取递归互斥信号量 
`vSemaphoreDelete()`: 释放递归互斥信号量
