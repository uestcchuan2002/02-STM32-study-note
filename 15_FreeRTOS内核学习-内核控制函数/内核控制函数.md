# FreeRTOS 内核控制函数

关于FreeRTOS 的内核控制函数有以下13个API函数：
- `taskYIELD()`                     |   请求任务切换
- `taskENTER_CRITICAL()`            |   在任务中进入临界区
- `taskEXIT_CRITICAL()`             |   在任务中退出临界区
- `taskENTER_CRITICAL_FROM_ISR()`   |   在中断中进入临界区
- `taskEIT_CRITICAL_FROM_ISR()`     |   在中断中退出临界区
- `taskENABLE_INTERRUPTS()`         |   打开中断
- `taskDISABLE_INTERRUPTS()`        |   关闭中断
- `vTaskStartScheduler()`           |   开启任务调度器
- `vTaskEndScheduler()`             |   关闭任务调度器
- `vTaskSuspendAll()`               |   挂起任务调度器
- `xTaskResumeAll()`                |   恢复任务调度器
- `vTaskStepTick()`                 |   设置系统时钟节拍计数器
- `xTaskCatchUpTicks()`             |   中断后修正系统时钟节拍


**一、核心概念**

这些函数主要控制三类事情：任务切换、临界区/中断屏蔽、调度器运行状态。FreeRTOS 内部通常通过任务控制块 `TCB`、就绪列表 `pxReadyTasksLists[]`、延时列表、挂起就绪列表 `xPendingReadyList`、系统节拍 `xTickCount` 等数据结构完成调度。

---

### 1. `taskYIELD()`

**作用**：主动让出 CPU，请求进行一次上下文切换。

**用法**：

```c
while(1)
{
    do_something();
    taskYIELD();
}
```

**实现思路**：本质是宏，通常映射到 `portYIELD()`。在 Cortex-M 上一般通过触发 `PendSV` 异常完成上下文切换。

**注意**：`taskYIELD()` 不会让当前任务进入阻塞态，只是把执行机会让给同优先级或更高优先级的就绪任务。如果没有合适任务，当前任务可能马上继续运行。

---

### 2. `taskENTER_CRITICAL()` / `taskEXIT_CRITICAL()`

**作用**：进入/退出任务级临界区，保护共享资源，防止任务切换和部分中断打断。

**用法**：

```c
taskENTER_CRITICAL();
shared_data++;
taskEXIT_CRITICAL();
```

**实现思路**：映射到 `portENTER_CRITICAL()` 和 `portEXIT_CRITICAL()`。内部通常会关闭或屏蔽可调用 FreeRTOS API 的中断，并维护临界区嵌套计数。只有最外层 `taskEXIT_CRITICAL()` 才真正恢复中断。

**注意**：临界区要尽量短，里面不要调用可能阻塞的 API，例如 `vTaskDelay()`、队列阻塞发送/接收等。

---

### 3. `taskENTER_CRITICAL_FROM_ISR()` / `taskEXIT_CRITICAL_FROM_ISR()`

**作用**：在中断服务函数 ISR 中进入/退出临界区。

**用法**：

```c
void Some_IRQHandler(void)
{
    UBaseType_t saved;

    saved = taskENTER_CRITICAL_FROM_ISR();
    /* 访问 ISR 与任务共享的数据 */
    taskEXIT_CRITICAL_FROM_ISR(saved);
}
```

**实现思路**：单核下通常对应 `portSET_INTERRUPT_MASK_FROM_ISR()` 和 `portCLEAR_INTERRUPT_MASK_FROM_ISR(x)`。进入时保存原中断屏蔽状态，退出时恢复。

**注意**：必须把进入函数返回的值原样传给退出函数。不要在 ISR 中使用任务版 `taskENTER_CRITICAL()`，也不要在过高优先级中断中调用 FreeRTOS API。

---

### 4. `taskDISABLE_INTERRUPTS()` / `taskENABLE_INTERRUPTS()`

**作用**：直接关闭/开启中断。

**用法**：

```c
taskDISABLE_INTERRUPTS();
/* 极短的硬实时保护代码 */
taskENABLE_INTERRUPTS();
```

**实现思路**：分别映射到 `portDISABLE_INTERRUPTS()` 和 `portENABLE_INTERRUPTS()`，属于移植层能力。

**注意**：它们通常不维护嵌套计数，误用容易提前打开中断。一般应用代码更推荐使用 `taskENTER_CRITICAL()` / `taskEXIT_CRITICAL()`。

---

### 5. `vTaskStartScheduler()`

**作用**：启动 FreeRTOS 调度器，开始多任务运行。

**用法**：

```c
xTaskCreate(Task1, "Task1", 128, NULL, 2, NULL);
xTaskCreate(Task2, "Task2", 128, NULL, 1, NULL);

vTaskStartScheduler();

while(1); /* 正常情况下不会运行到这里 */
```

**实现思路**：创建空闲任务 Idle Task；如果启用软件定时器，还会创建 Timer Service Task。随后初始化 tick 中断，设置 `xSchedulerRunning = pdTRUE`，再调用 `xPortStartScheduler()` 启动第一个任务。

**注意**：如果堆内存不足导致 Idle Task 或 Timer Task 创建失败，函数可能返回。

---

### 6. `vTaskEndScheduler()`

**作用**：结束调度器，停止多任务运行。

**用法**：

```c
vTaskEndScheduler();
```

**实现思路**：调用移植层 `vPortEndScheduler()` 停止调度器相关中断，并将调度器运行状态置为停止。

**注意**：很多 MCU 移植并不真正支持这个函数，常见嵌入式项目里很少使用。它不是系统复位函数。

---

### 7. `vTaskSuspendAll()`

**作用**：挂起调度器，防止任务切换，但不中断硬件中断。

**用法**：

```c
vTaskSuspendAll();

/* 执行较长但不希望被任务切换打断的操作 */

xTaskResumeAll();
```

**实现思路**：增加 `uxSchedulerSuspended` 计数。调度器挂起期间，当前任务继续运行；中断仍然可以响应，tick 也可能被记录为挂起 tick。

**注意**：它和临界区不同，不会关闭中断。挂起调度器期间不要调用可能引起阻塞或任务切换的 API。

---

### 8. `xTaskResumeAll()`

**作用**：恢复被 `vTaskSuspendAll()` 挂起的调度器。

**用法**：

```c
vTaskSuspendAll();

/* 临界操作 */

if (xTaskResumeAll() == pdFALSE)
{
    taskYIELD();
}
```

**实现思路**：减少 `uxSchedulerSuspended`。当嵌套计数归零时，FreeRTOS 会处理 `xPendingReadyList` 中的任务，补偿挂起期间积累的 tick，并判断是否需要上下文切换。

**返回值**：如果恢复调度器导致了上下文切换，返回 `pdTRUE`；否则返回 `pdFALSE`。

---

### 9. `vTaskStepTick()`

**作用**：在 tickless idle 或低功耗模式下，系统睡眠期间 tick 中断被抑制，唤醒后用它一次性推进系统 tick。

**典型位置**：主要由移植层或低功耗代码调用，普通任务代码一般不直接用。

```c
vTaskStepTick(xSleepTicks);
```

**实现思路**：直接增加 `xTickCount`，但要求不能越过下一个任务超时时刻 `xNextTaskUnblockTime`。如果刚好到达任务应解除阻塞的 tick，会通过挂起 tick 机制让后续 `xTaskIncrementTick()` 正确唤醒任务。

**注意**：它不会为每一个跳过的 tick 都调用 tick hook，也不适合用来处理已经错过任务唤醒点的情况。

---

### 10. `xTaskCatchUpTicks()`

**作用**：当应用长时间关闭中断导致错过多个 tick 中断时，用它补偿系统 tick。

**用法**：

```c
/* 假设 missed_ticks 是应用自己计算出来的丢失 tick 数 */
xTaskCatchUpTicks(missed_ticks);
```

**实现思路**：内部先挂起调度器，把需要补偿的 tick 加到 `xPendedTicks`，再通过 `xTaskResumeAll()` 逐个处理这些 tick。和 `vTaskStepTick()` 不同，它允许推进过程中越过任务超时时刻，因此可能唤醒阻塞任务。

**返回值**：如果补偿 tick 后触发任务切换，返回 `pdTRUE`，否则返回 `pdFALSE`。

---

**二、对比记忆**

| 函数 | 是否关中断 | 是否阻止任务切换 | 典型用途 |
|---|---:|---:|---|
| `taskENTER_CRITICAL()` | 是 | 是 | 短临界区 |
| `vTaskSuspendAll()` | 否 | 是 | 较长但不能被任务切换打断的代码 |
| `taskDISABLE_INTERRUPTS()` | 是 | 是 | 极底层、极短保护 |
| `taskYIELD()` | 否 | 否 | 主动让出 CPU |
| `vTaskStepTick()` | 否 | 间接相关 | tickless idle 时间快进 |
| `xTaskCatchUpTicks()` | 否 | 内部短暂挂起 | 补偿丢失的 tick |

**三、学习重点**

最容易混淆的是临界区和挂起调度器：临界区会影响中断，适合短代码；挂起调度器不影响中断，适合较长操作。`vTaskStepTick()` 偏底层低功耗移植，`xTaskCatchUpTicks()` 偏 tick 补偿。`taskYIELD()` 只是主动请求调度，不等于延时，也不等于阻塞。
